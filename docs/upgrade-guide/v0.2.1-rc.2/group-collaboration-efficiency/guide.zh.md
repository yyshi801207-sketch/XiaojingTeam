# 群消息分派与复核交付

[English](guide.md) | 中文

## 变更

未点名的新群消息仅交给当前普通成员中的群主；没有合适群主时交给首位普通成员。明确点名时只选择对应成员。已接受输入记录 `collaborationVersion: 1` 及固定接收者。旧的已接受输入保留原接收者和旧执行行为，不重写其文件或日志。

成员上下文包含未读的公开消息，首次参与提供有上限的近期历史，原文通过 `read_group_history` 查询。`plan_group_work` 允许空分工列表，并记录是否需要另一成员复核。财务结论、数据修改和明确要求复核的成果必须取得绑定准确候选版本及子任务的独立通过意见；缺少复核时不能正式完成。模型负责判断任务类型，不保证所有重要任务均分类正确。

对于带版本的群任务，`report_group_blocker` 记录未完成原因、成员报告的执行影响和安全的下一步，然后结束任务，不产生已批准的交付回执。鉴权、权限、缺少资料、服务故障和复核不可用采用同一出口。已可靠保存的子任务失败以 `status: failed` 和诊断返回等待中的调用者，不取消调用者，也不满足分工完成或复核要求。调用者应报告或处理阻塞，不得宣称成功或盲目重复写入。正在执行的复核人会在计划记录前被拒绝，其中包括正在等待本成员的调用者。影响未知、取消及持久化未确认仍保留暂停与核验保护。重启从原始成功工具结果恢复阻塞报告，不批准交付，也不重放操作。

## 迁移

1. 保留已有群数据和 Session 日志。可选输入版本区分旧的已接受任务和新任务，无须改写旧记录。`/chats` 插件现在要求组合中提供 `fs` 服务，用于检查复核候选内容。
2. 更新要求每名 Bot 回答所有消息的职责说明。需要其他成员参与时，明确点名或调用 `request_group_member`。普通任务可通过空分工的 `plan_group_work` 独立执行；重要任务选择另一位当前成员复核。
3. 自定义 `/chats` 配置可设置 `initialHistoryMessages`（默认 20）、`historyPageSize`（20）、`historyPageMaxChars`（16000）及 `reviewCandidateMaxBytes`（累计 8388608 字节），均须为正整数。已有配置自动使用这些默认值。
4. 通过 `request_group_member` 提交原始候选内容，只有对应复核子任务可调用 `submit_group_review`。根据意见修改后重新提交候选版本。原审批权限仍控制外部修改，复核不提供回滚。
5. 确认未点名消息仅唤醒负责人，明确点名只选择相应成员，旧排队输入保留原接收者，未通过复核或之后被修改的重要成果仍无法正式交付。使用相同模型和任务对照后，再判断真实模型质量和计费节省。历史及复核限制见[包参考](../../../../packages/api/katcats-team/README.zh.md#group-conversations)。
