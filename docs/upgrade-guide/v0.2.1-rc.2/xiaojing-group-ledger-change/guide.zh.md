# 群组任务档案与账套切换

[English](guide.md) | 中文

## 变更

群组仍有待处理或暂停的运行时，群设置和 `katcatsChats/bindFinance` 拒绝更换账套。此前保存的运行未结束时也可更改绑定。群组任务按档案关联的账套继续。

当前版本可读取旧任务档案。保存的待验收和已完成状态需要由更新后的档案读取器读取。群聊内单独发送的验收确认会保存为一条没有派工接收者的用户消息。旧版本要求每条保存的群组输入都有接收者。

普通任务的提交成果通过必要复核并可靠发布后，现在直接完成。只有标记需要人工复核的任务才等待用户验收。当前负责人也可按自然语言理解验收确认，保存时保留原执行接收者，旧读取器不能打开这类记录。Odoo 操作审批仍单独进行，发生在写入之前。

群组已声明的数据修改必须在发送前复核准确的 Odoo 目标和规范化操作。复核回复不再算作独立业务分工完成，候选声明的制作者不得批准本人工作。未知写入结果在重启后仍保持未确认。

## 迁移

1. 在群聊中结束当前运行，或使用「停止」。如果此前的操作结果未知，先检查已保存的结果。
2. 在群设置中打开「财务连接」，更换并验证账套。已有任务档案仍可查看。打开档案确认哪些任务可在当前账套继续。
3. 提交或验收档案任务，或在群聊内单独发送验收确认后，继续用更新后的版本打开该数据目录。如需使用旧版本，使用更新前备份的数据。
4. 对于尚无验收条件的开放任务，让负责人在原任务 ID 上补齐条件后再提交成果。只有用户必须复核最终成果时才设置 `human_review_required`，不要用它重复已完成的操作审批。
5. 对待执行的 Odoo 修改，使用 `review_candidate.odoo_operation` 及相应 `source_delivery_ids` 重新请求复核。执行后回读记录并复核最终成果。若此前写入结果未知，先检查记录再决定是否需要重试。
