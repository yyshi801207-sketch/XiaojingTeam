# Katcats.AI 群聊发送保留当前工作

[English](guide.md) | 中文

本指南仅适用于独立 Katcats.AI 产品。

## 变更

群输入框的普通发送使用 `queue`，不再自动调整当前工作。产品保存并确认收到各条消息，同时保留正在执行的成员和审批。成员正在等待同事结果时，要等这条执行链完成后再回答排队的追问；同一成员 Session 不会并发运行第二个模型。其他群和私聊不受影响。

轮次上限暂停期间的排队消息不再启动替代轮次或取消已接受的任务。手动暂停、轮次上限暂停及结果未确认的暂停在普通发送后仍保留；允许继续时，“继续”沿用现有成员派活。已停止或已完成的群收到新的普通消息时启动新轮次。明确选择“打断并调整”或 Host 传入 `mode: 'steer'` 时，仍在持久接受替代指令后取消并等待旧执行链结束。已完成回复、回执和文件均保留；取消不能撤销已开始的外部操作，也不能把未知结果标为成功。同一请求重试只确认已保存输入，不重复接受。

## 迁移

1. 使用更新后的独立 Katcats.AI 版本，沿用其现有产品数据位置。存储字段、Session 代和文件位置均无需迁移，不要编辑配置或移动数据。
2. 在成员工作时普通发送一个问题，确认显示接收反馈且原任务和审批没有被取消，成员完成当前工作后才回答。群已暂停时，先核对原因，并在允许时点击“继续”。
3. 原先依靠排队消息替换轮次上限暂停任务的集成，须向 `katcatsChats.sendMessage` 明确传入 `mode: 'steer'`。群界面只在确实需要替换工作时选择“打断并调整”；重复结果未知的外部操作前，先核对已保存进度。重试保持相同请求 ID 与内容，内容变化时使用新的请求 ID。

失败处理和历史保留保证见[群聊说明](../../../../packages/api/katcats-team/README.zh.md#group-conversations)。
