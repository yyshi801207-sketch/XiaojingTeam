## 配置与归属

主 Bot 区域可收起为紧凑的一行，保留对话与总调度室入口。折叠选择保存在浏览器本地，重载后恢复，与分组折叠和成员记录相互独立；旧偏好默认展开。窄侧栏保留原有头像操作。

`workspaceRoot` 必须为绝对路径。每个成员使用 `workspaceRoot/bots/<BotId>` 目录，创建前拒绝目录链接。`mainName`、`mainRole`、`ordinaryGroupName` 和 `chatGroupName` 配置首次使用的名称。移动成员的逻辑分组不改变文件或 Session 身份。

每个私聊 Session 归属于成员已分配目录所注册的 DSH 文件工作区。该登记启用现有对话与输入框，独立于逻辑 Bot 分组。新成员仅在工作区登记及 Session 关联成功后发布。启动时使用现有成员的已分配目录修复缺失登记或关联，不替换 Session ID、不移动文件、不改写聊天历史。工作区身份保存在现有 DSH 名录中，不向成员记录增加字段。

Host 通过 `ctx.katcatsTeam` 提供服务，生成的 Remote 命名空间为 `katcatsTeam`。仅所有者可以读取或订阅快照、创建成员与分组、编辑成员身份与外观，以及重命名、排序或删除自定义组。Bot 和群聊共用自定义分组。删除自定义分组时，先通过一次群目录写入将其中的群聊移回系统群聊分区，再通过一次团队目录写入将 Bot 移回“未分组”并删除该组。写入中断或失败仍保留有效引用，可以重试；第二次写入失败时分组仍保留。Bot 与群聊身份、Session 和工作文件保持不变。主成员和两个系统分组始终保留。快速创建只需要名称和可选的已批准头像，生成通用助手，不调用模型。

主 Bot 默认名为“小兢会计”。使用默认配置时，启动会通过已有的待完成改名事务，将已保存的主 Bot 旧名“Katcats”及其 Session 标题一起更新，保留原身份、聊天记录和工作文件。用户自定义的主 Bot 名称以及名为“Katcats”的普通成员保持不变。

新成员跟随 DSH 当前基础模型，创建时不要求已有凭据或可用模型目录。消息准入钩子在图片校验前解析该策略，使用[仅修改当前 Session 的选择 API](../session-controller/README.zh.md)，不保存应用默认值，也不改变其他 Bot。固定选择保留标准化的覆盖值。已有 `follow-global` 记录开始跟随后续基础模型变化，无须重写成员记录。产品管理的群派活和继续操作也解析该策略；无关的直接 SDK、ACP 或定时 followup 不经过此消息准入钩子。

成员设置读取共享[模型目录](../../client/ui-model-selection/README.zh.md)。在“设置 → 模型”保存候选模型后，每个 Bot 的选项自动更新，无须重启；ChatGPT 候选必须通过连接测试后才能保存。模型更改在保存成功前属于草稿，成功后用于该成员的新消息，不改变其他 Bot 或应用默认模型。设置区分已保存路线与最近一次有记录的请求模型；排队的选择不算实际请求。凭据和提供方变化刷新共享目录；更换 Host 时清除旧选项；迟到响应不能覆盖新选项或在销毁后发布。

Client 替换工作区列表 slot，并注册一个工作区分类，其激活操作打开同一创建窗口。保留现有对话、输入框和右侧工具，在新增标签中显示成员设置。明确选择成员或创建新的 Bot、群聊时，对应输入框视图提交且公开侧栏界面可用后，才展开设置，包含空白对话；导航失败与设置失败分别报告。普通成员可从十款豆子 Bot 剪影中选择；透明 PNG 遮罩保留独立选色，已有形状 ID 保持兼容；选择图标不会修改 Bot 已保存的真实职责。主 Bot 固定使用用户提供的小兢人像，不受已有形状与颜色影响，其设置不提供普通成员的外观选择器。设置页中的工作目录当前只读。

每次打开应用都进入已有的主 Bot 对话，右侧栏保持收起，包括首次使用、没有普通 Bot 的团队和之前保存为展开的侧栏。启动时等待两个产品目录以及可用的主会话；会话目录刷新或原生历史选择不会提前消耗这次导航。用户明确选择 Bot 或群聊后，待完成的启动导航让位，后续目录更新和重连保留用户选择。手动打开设置会取消待处理的启动收起请求。启动不会创建独立的通用 Agent 对话，也不清空主 Bot 历史。主 Bot 和普通 Bot 的空白对话在输入框上方显示用户提供的团队插画及相同的本地化财务团队标题：中文为“小兢会计，您的AI财务团队”，英文为“Xiaojing Accounting, your AI finance team.”。

侧栏以更大的无底框头像显示用户提供的主 Bot 人像，对话标题栏和设置页使用同一人像。已有普通头像的形状 ID 和颜色继续有效；普通群负责人仍使用选中的豆子 Bot 头像，并以独立的小菱形标记身份。“创建分组”入口位于自定义分组上方，随后是群聊和未分组，各分区可独立折叠。没有保存条目顺序时，默认创建的新 Bot 排在未分组顶部，明确选择分组时仍放入指定分组。新分组排在已有分组之前；没有保存条目顺序时，新群聊排在已有群聊之前，置顶条目保留优先级。分区数量以括号形式紧跟名称显示。每个分区统计其中的 Bot 和群聊条目，每个群聊计为一个单位；每条群聊显示已保存的成员数。自定义分组菜单支持在自定义组顺序中上移、下移，或打开删除确认；边界移动禁用，系统分区固定。顺序沿用现有分组数组保存，重启后保留。Bot 与群聊共用置顶、移至、重命名、复制 ID 和删除菜单，可以通过操作按钮或右键打开；移动只改变逻辑归组，所属类型的系统分区始终可选。重命名使用仅编辑名称的对话框，删除需要确认，并且只有 Host 确认保存后才更新。列表可滚动但不显示滚动条，下方仍有内容时提供继续查看按钮。新建 Bot 或群聊被选中时，会展开所在分区，并仅滚动侧栏列表，在可用滚动范围内将该条目居中显示。Katcats 产品组装将主操作改为“创建新 Bot”，全局工具默认折叠，用量排在其下方。

同一分区内的 Bot 与群聊可以拖至其他条目的前方或后方，条目本身跟随鼠标或手写笔移动，相邻条目滑动让位，松手后保存目标位置。置顶与非置顶条目分别排序，主 Bot 固定。Esc 或指针操作中断会取消预览；触摸仍可正常滚动，减少动态效果设置会关闭相邻条目的过渡动画。混合条目顺序保存在浏览器本地侧栏偏好中，刷新和重启后保留，不修改成员归组或 Session 记录。新条目排在相应置顶层已保存条目之后，删除或离组的条目不再显示。取消拖动或拖至其他分区不会改变顺序。

删除 Bot 要求其私聊 Session 空闲、不属于任何当前群聊，且没有活动自动化或其他已报告的 Session 活动。删除群聊先停止其工作，再移除目录条目及派发日志；活动自动化必须先停止。两种操作均通过现有工作区名录归档确切的所属 Session，保留聊天历史和工作文件。目录写入失败时只回滚本次删除新增的归档变化；回滚未完成会明确报错，不报告成功。已保存的记忆和自动化记录不会被删除。

Bot 与群设置首次采用现有最小宽度，本次运行按设置 provider 保留手动宽度。Bot、群聊与全局设置的分区标题加粗显示。表单可滚动且隐藏滚动条，群成员列表可折叠。主 Bot、普通 Bot 和群聊分别使用类型化词典中的专属输入提示，不覆盖阻塞、不可用、排队或计划模式的操作提示。输入框隐藏工作区、模式、模型和权限控件，保留原编辑器、附件和发送；模型仍在 Bot 设置中选择。权限在设置面板复用原选择器及风险确认：Bot 对应自身私聊，群成员行仅对应该成员在本群的执行会话，均不修改全局默认。面板隐藏、成员不可用或断线时释放群会话引用；连接重置后重新打开两个目录流，保留的目录在新快照到达前显示加载状态。缺少群绑定时不回退到群记录或私聊会话。

群设置还支持一次选择统一应用于所有已保存的普通成员，共用一次风险确认，并保留成员单独入口。全部精确群执行会话、权限投影及命令访问必须先就绪。未保存修改、保存中、面板隐藏、不支持的旧成员或断线时，批量设置不可用。成员通过公开权限命令依次更新，期间锁定单独入口；成员名录或连接变化会使确认失效。取消或命令结果未确认后停止后续派发，逐项显示已应用、未执行、命令不可用或结果未确认。已应用的更改不会撤回，未确认的结果需检查该成员权限。私聊、其他群与全局默认保持独立；任一成员采用财务预设时，不提供自动审批选项。

群聊以及与主 Bot、普通 Bot 私聊中的用户消息在浅色模式下使用黑底白字，在深色模式下使用白底黑字。用户气泡采用共享标准圆角和内边距，不保留可见内描边。头像颜色保持独立。

## 就地操作

Bot、群聊与侧栏自定义分组的右键菜单在鼠标位置打开，操作按钮仍在按钮旁打开菜单。成员消息支持复制记录中的正文和消息 ID，头像及姓名菜单支持复制记录中的发送者姓名或打开当前成员。调度室人员卡与交接姓名可打开已有成员详情或复制名称。任务档案支持查看详情、复制目标和任务 ID。已移除成员的历史姓名仍可复制，不可用的导航会禁用。这些操作复用共享 [ContextMenu](../../client/ui-primitives/README.zh.md) 的键盘与焦点行为，不启动模型调用。复制成功或剪贴板失败会显示应用通知。设置菜单跟随宿主主题，调度室菜单保留橙色强调。

## 对话管理成员

主 Bot 查看成员名录、创建具有长期职责的成员并修改成员头像。启用群聊服务后，它可以按要求用已保存的普通成员创建群聊，并指定其中一位成员担任负责人；主 Bot 自身不参与群内任务执行。每个成员仅可保存自己的私聊职责；工具发现与执行都会核对真实存活的 Agent 及其成员身份。职责文本不授予工具、不改变权限、模型或工作目录。快速创建仍生成通用助手，单次任务不会隐式改变已保存职责。

对话创建与菜单共用串行化成员操作，首次持久化创建意图即包含职责和所选头像。结果报告实际提交的成员，不把拟定身份当作创建成功。每个已保存的新 Bot 会切换到其空白私聊；随后新建的群聊会切换到该群聊首页。设置保留明确编辑的草稿，仅提交修改过的字段，因此保存外观不会覆盖对话工具刚保存的职责。Web 使用现有通用工具卡展示实际参数与结果。

仅主 Bot 可用的 `create_bot` 接受可选 `avatar`，包含十款豆子 Bot `shape` 之一和八种预设颜色之一；省略时保持 `classic` 和 `#FF2849`。`create_bots` 接受本次完整创建批次，包括名称、职责及可选头像。颜色限制仅按本批计数：前八位使用不同预设色，重复或省略的颜色会分配为尚未使用的预设色，之后的成员才可使用其他六位颜色值。已创建的 Bot 不占用本批颜色。开始创建前校验全部输入；后续存储或 Session 失败会停止批次，但不会回滚已保存成员。先用 `list_bots` 核对，再仅补建缺失成员。仅主 Bot 可用的 `set_bot_appearance` 修改既有成员所需头像，不改变职责、模型、分组、Session 或工作目录，也不能用来绕过创建配色规则。结果均包含实际保存的头像。

确认所有所需成员均已保存后，`create_group_chat` 通过与手动建群相同的持久化名录保存群及可选负责人。侧栏显示已保存的群；创建本身不会派发任务。群名、成员和负责人完全相同的调用会复用已保存的群，并发调用也不会重复创建。`list_group_chats` 恢复待完成的创建并返回群信息，不包含聊天记录。失败或取消后，应先查看群信息，再决定重试或报告群已就绪。

`list_bots` 将系统默认 Bot 分组显示为“未分组”，不重命名既有持久化分组或用户自定义名称。把颜色写进职责文本不会修改头像；主 Bot 根据已保存结果确认外观。

变更准入前检查取消。持久化意图接受后，即使调用方取消，也会完成一致性处理。因此取消、中断或失败结果可能与已保存成员或外观修改同时存在。工具指导要求主 Bot 在重试前先查看名录，不自动重复修改。恢复会复用匹配的未完成意图；创建完成后的新调用属于新操作，不承诺恰好执行一次。

<a id="group-conversations"></a>

## 群聊

群组设置中的任务档案位于基本信息下方，跟随宿主的浅色或深色主题，使用数豆绿色强调。只有从两个调度视图打开的档案固定使用深色背景与橙金色强调。

群组设置、群组调度室以及总调度室的选中群组可打开同一份只读任务档案。左侧任务索引集中显示记录数量、搜索和受阻筛选，紧凑顶栏显示群名与连接状态。详情展示目标和下一步，验收条件与产物引用在宽屏并列、窄屏上下排列。已登记与受阻状态均带文字和彩色标记。搜索与受阻筛选仅作用于本群已保存的业务记录。档案打开期间跟随已确认的目录更新，显示保存修订，并在断线时标明旧数据；普通工具调用和成员回合结束不会更新业务阶段或代表验收通过。任务交接列表默认跟随新记录，手动上翻或跳到顶部后暂停跟随，点击到底部恢复。这些控制只滚动交接列表，执行动态区保持原位。

新用户输入保存 `coordinationVersion: 1`。`record_group_task` 记录业务目标、负责人、验收条件、阶段、下一步、产物引用和准确的用户消息身份。直接接收者可以明确延续自己已有的跨轮次任务；被派工成员继承关联，不能重新归类。`plan_group_work` 为尚未归类的直接请求创建开放任务，验收条件在明确记录前保持未指定。回复、阻塞说明和成员轮次结束均不代表业务验收通过。`find_group_tasks` 仅查询当前群，结果数量受 `historyPageSize` 限制。

自动追加的上下文排除明确属于其他业务任务的正文。未归类消息仍为公共上下文，以保留更正及共同约束。当前输入及允许读取的交接来源完整保留；`read_group_history` 仍允许按需查询可见原文。归类由模型判断，必要时向用户澄清。原有成员 Session 历史不被删除，也不拆为独立任务 Session；本次减少的是新增的无关正文注入，不保证严格上下文隔离或固定 token 节省比例。

已确认阻塞会为合适的任务负责人或群主保存一次性的解释义务。等待中的调用者保存回复或阻塞报告后，该义务即被满足；否则群驱动器在已有工作结束后启动解释。解释不重做失败操作，也不绕过独立复核。重启保留待办，但等待明确继续；未知结果仍须核验，停止会取消待解释义务，解释未完成时明确暂停，不无限续轮。

群聊标题栏可按需打开以已保存群名称命名的调度室。HQ 场景展示真实成员身份和已记录的任务交接，并提供独立、可访问的成员与任务列表；不显示底部部门进度栏、模拟任务、虚构百分比或 token 估算。关闭调度室会释放 iframe 及其渲染器。入口负责加载调度室样式，并向延迟加载的场景传入类名，避免启动依赖共享样式分块。场景改编自带许可的 HQ 素材，保留可见署名和 `artwork/hq/LICENSE` 中的许可文件。

实时模式读取群名录、任务生命周期日志、公开回复，以及现有待回答问题和审批状态。回放只推进本地根 Session 序号游标，不调用模型、执行工具或改变任务状态。更早的历史按需加载，缺失或恢复的记录明确标注。已记录参与者身份补充当前名单，不重建未记录的成员变更。公开复核意见仍作为回复展示，不视为机器确认的复核通过；回答问题、批准操作和打开已登记交付文件仍使用原群聊。总调度室不属于此视图。

实时执行面板只保留当前群执行成员的 Session 读取引用，展示已加载记录中最近 100 条执行动态，包括步骤、工具请求、嵌套工具执行及结果状态；面板不展示回复正文、推理、参数或工具结果正文。每行动作状态在成员姓名和时间之前；超长状态文字横向滚动，悬停暂停，并遵守减少动态效果设置。向上滚动暂停自动跟随，任务交接列表提供到底部按钮。关闭面板、切换回放或卸载插件会释放读取订阅，不停止任务；重连后重新获取执行会话引用，记录不可用时明确提示。回放隐藏实时执行动态。这些视图不会调用模型。

场景使用原生 HQ 发光弧线展示已记录的交接，仅活动交接带有流动光点。实时模式中，名录里的群外 Bot 以访客身份在公共走廊走动，身份标签默认隐藏，仅在鼠标移到小人身上时显示，移开后再次隐藏；访客不加入任务，也不获取群执行会话；回放不展示这些环境访客。透明文字叠层沿用原生 HQ 的字体层级和配色。右上角可循环切换全景、巡游和俯视，个人视角按真实身份定位和跟随。焦点位于场景内时也可按 Esc 关闭调度室，不停止任务。底部任务进度横线统计当前显示轮次的已记录派工状态，不推算整个项目的完成度。人员管理采用紧凑、可搜索的只读名录，支持负责人和群成员筛选，显示单行职责、已保存的模型配置、当前群执行会话权限及实时状态。详情展开完整职责、模型服务商、推理强度和群工作文件夹。权限不读取 Bot 私聊会话；未读取或断线时标注暂未读取，回放中的人员管理同样读取当前配置。小型执行动态区固定在独立滚动的交接区上方。交接默认折叠，显示发起人、接收人、任务简述和状态，展开后保留完整指令与回复；不展示底部成员条。悬停或聚焦场景名称框可查看 Bot 的完整职责、群内角色和状态，点击成员筛选交接。运行时长位于紧凑的群标题下方，与 Token 统计分开。拖动标题只移动调度室浮层，整个对话框禁用原生窗口拖动。

本群用量按已投递群输入的轮次身份汇总已返回的模型尝试记录，以轮次、步骤和重试身份去重。用量面板复用已上报的输入、缓存及输出计数，不重复累计推理 Token。缺失用量、未加载历史或无法归属的尝试会标注；不读取私聊或访客会话。调用次数统计已返回尝试，不含单独摘要等辅助调用。账户费用账本无法按群归属，因此不显示费用。

侧边栏主 Bot 黑色身份标签右侧的分派节点图标打开独立的总调度室组件，悬停显示“总调度室”；收起侧栏时入口保留在主 Bot 头像下方。头像与名字仍打开主 Bot 对话。中央办公室绑定名录中的 `mainBotId`；每个群组占据一个带工位的房间，已保存的群主坐后方独立桌，成员各占一个工位。成员增加时增设桌排并缩放家具。房间位置在窗口生命周期内保持稳定，每层容纳八个群组。同一 Bot 在不同群中有独立形象和执行状态；独立 Bot 展示在公共区域。点击房间或底部群组条，只订阅选中群组的执行动态和用量，并先释放上一组订阅。固定动态区与独立滚动的交接区显示选中群组的当前回执；完整历史和回放保留在独立群组调度室。缺失数据保持不可用状态，关闭任一视图均不取消任务。两种调度室默认打开时均受共享弹窗安全区域约束，不遮挡原生窗口控制按钮。任务档案采用紧凑页头、醒目数量与独立滚动的列表和详情；已登记及受阻状态以文字和彩色标记区分，验收条件及产物数量仅统计已保存条目，不代表完成。

总调度室后排的群组导视牌以短支杆直接连接后墙顶沿，侧面房间显示在对应的左右外墙旁，与成员标签分开。成员标签复用悬停框，以文字颜色区分状态，悬停时展开职责。全屏切换保留所选群组和视角；Esc 先退出全屏，再关闭总调度室。顶部按身份去重统计群聊及私聊中正在执行的 Bot，并统计实时处理任务的群组；断线时不显示实时计数。时钟采用设备本地时间。人员管理按群组展示全部已创建 Bot，另列主 Bot 与未入群 Bot，总人数按身份去重。权限只显示当前已订阅群组中加载完成的执行会话记录。底部完成度为当前轮次的已完成派工数除以已记录派工数，空闲时使用最近保留轮次；明确不参与的派工不计入分母。失败或结果未知不计入完成，无任务不显示百分比，新增派工可能使比例下降。此数值表示派工完成度，不代表业务成果已验收。

对于带版本的群任务，`report_group_blocker` 记录未完成原因、成员报告的执行影响和安全的下一步，然后结束任务，不产生已批准的交付回执。鉴权、权限、缺少资料、服务故障和复核不可用采用同一出口。已可靠保存的子任务失败以 `status: failed` 和诊断返回等待中的调用者，不取消调用者，也不满足分工完成或复核要求。调用者应报告或处理阻塞，不得宣称成功或盲目重复写入。正在执行的复核人会在计划记录前被拒绝，其中包括正在等待本成员的调用者。影响未知、取消及持久化未确认仍保留暂停与核验保护。重启从原始成功工具结果恢复阻塞报告，不批准交付，也不重放操作。


独立的 `/chats` Host 入口提供 `ctx.katcatsChats` 及 `katcatsChats` Remote 命名空间，要求相同的绝对 `workspaceRoot`；`relayLimit` 默认限制每轮全群成员启动任务的总次数为 16，既有群保留已保存的上限。每个群使用 `workspaceRoot/chats/<ChatId>`。新群仅包含明确选择的普通 Bot，至少一名成员，负责人可选；不自动加入创建助手。所有者可以在群设置中指定、更换或清空负责人。手动建群窗口限制在可用窗口高度内，内容超出时在内部滚动，取消和创建按钮始终可见。

群根 Session 只保存聊天记录，不发起模型请求。原输入框通过精确 Session 的传输注册提交用户消息和停止群内工作，私聊、内部执行及无关 Session 路由保持原样。每名普通成员在每个群另有执行 Session；两个群和一个私聊不会复用同一成员的 Session。群会话共用本群工作目录，提示词采用群内职责覆盖值或已保存成员职责，以及本群公开上下文，不复制私聊历史。内部执行 Session 不会在团队侧栏变成额外成员。

明确点名时只按已保存名录顺序选择被点名成员。未点名的用户消息仅交给当前普通成员中的群主；没有合适群主时交给首位普通成员，但不保存新的群主。初始接收者与 `collaborationVersion: 1` 一同提交，重试和重启不重新选择。没有该版本的已接受输入保留已保存的接收者和旧执行规则。成功跳过会结束无关轮次，不生成聊天气泡。成员请求等待对方实际完成回复或确认跳过，在发布后返回已保存结果和回复身份。忙碌目标立即拒绝，避免循环等待；回复不触发全员广播。派活仅向成员的群执行 Session 应用其当前模型策略。

每个执行会话按身份接收尚未读过的公开消息，相同文字但身份不同的消息分别保留。当前用户内容、附件和交接指令仅提供一次；已确认结果在群记录尚未发布时仍可读取。带版本的上下文清单与已准入成员输入一起持久化，准备和排队均不代表已接收。没有保留清单时，`initialHistoryMessages` 默认提供最近 20 条允许读取的公开消息，以及当前任务。正常 Session 压缩沿用摘要记忆和投递身份；裁剪或替换历史后按保留事件重新计算。`read_group_history` 按消息身份、关键词或游标读取当前任务允许访问的群历史，不能读取私聊、其他群或之后才接受的用户任务。`historyPageSize` 默认每页 20 项，`historyPageMaxChars` 默认每页 16000 个文本字符；部分结果提供继续读取的游标。涉及旧数字、历史决定和证据时，应查询原文核验，不能将摘要视为证明。

用户可以通过群内对话指定负责人和成员职责。实际执行成员的作用域职责工具先保存请求的群设置，再报告成功。变更保留私聊身份、其他群、权限授权及历史发送者快照。所有者设置替换明确的职责列表，对话变更只替换点名成员的职责。

每名成员的提示词包含名录、身份和生效的群内职责。带版本的任务通过 `plan_group_work` 记录自身任务、可选的同事分工及复核原因，空分工列表允许独立完成。成员可以在记录计划前通过 `ask_user_question` 澄清需求；业务操作仍须先记录计划。财务结论、数据修改和用户明确要求复核的成果必须由另一位当前成员复核。模型判断任务类型；运行时强制执行已记录策略，不保证语义分类绝无错误。其他成员完成前允许读取、计算及准备草稿，已声明的分工仍须取得真实结果后才能正式交付。单独调用成员请求执行派工，不增加协调模型。公开交接原文保留为群数据，不导入私聊或伪装为 assistant 发言。

`request_group_member` 可将待复核文字及已有文件绑定到一个父任务和一个复核子任务。Host 通过配置的 `fs` 服务捕获准确内容版本；`reviewCandidateMaxBytes` 默认限制文字及文件累计为 8388608 字节，超出时拒绝而不截断。只有对应复核子任务可以调用 `submit_group_review`。相同候选内容已完成并持久化的通过意见才能放行；普通回复、自我复核、未知结果及其他版本的意见均无效。展示和完成时再次检查文件内容。候选内容包含文字时，最终文字须与已通过文字一致，文字与文件一同复核时也适用。候选内容只有文件时，不对收尾说明进行语义比较。候选内容修改后必须重新复核。正常执行与重启恢复共用完成检查，最多追加一次纠正通知，之后明确报告复核未完成。没有可用复核者时，重要任务保留为草稿。原权限与外部写入审批仍然生效，复核不增加事务回滚。

本群驱动依次安排成员的初始接话机会。派活工具保持独占、按顺序执行：被派活成员使用自身空闲的执行会话工作，调用方等待其结果，同一执行会话不接受两个正在执行的任务。派活后，调用方同一模型步骤的其他工具会被拒绝，待新步骤读取真实结果后再执行。当前成员及其等待的依赖任务完成后，排队的用户输入优先于旧自动接力，获得有独立预算的新轮次；后续输入保持原有顺序，以及稳定的消息和请求身份。持久回执保留发送者姓名和头像快照。先刷盘成员 Session，再提交回执，随后把回复追加并刷盘到聊天记录，不唤醒根 Agent；稳定的输入与回复身份防止重试后重复展示。Client 用头像和姓名标明成员，正文放入独立的背景、细边框及圆角气泡，并适配深色主题。历史根会话回复保留原有归属。

群里的普通发送使用 `queue`：保存并确认收到消息，不取消正在执行的成员及其审批。忙碌成员在当前执行及其等待的真实结果完成后，再回答排队的追问，不在同一成员 Session 中并发运行第二个模型。手动暂停、轮次上限暂停和结果未确认的群收到排队消息后仍保持暂停。允许继续的暂停轮次通过“继续”恢复原有派活；已停止或已完成的群在下一条普通消息到达时启动新轮次。只有明确点击“打断并调整”或 Host 传入 `mode: 'steer'` 才替换当前轮次：先准入附件并一起保存新指令和新轮次，再取消并等待所捕获的旧执行链及其审批结束，随后启动新轮次。连续发送只在本群内串行交接，不延迟其他群。已保存消息、已完成回执和文件均保留，已经开始的外部操作无法回滚。相同请求重试复用已保存输入，不再次中断；私聊传输不变。接受前保存失败时保留旧轮次；接受或取消结果无法确认时，群里报告错误并停止依赖执行，等待核对。

输入框上方以头像、姓名和各自的处理、审批或等待回答阶段显示真实运行成员。多人每四秒轮换一次，悬停、键盘焦点或页面隐藏时暂停轮换；减少动态效果时静态列出，轮换不反复向读屏播报。成员消息、交接、任务身份、审批和群设置中的中性小菱形标记表示当前已保存的群负责人，按 Bot ID 匹配并保留历史发送者姓名；私聊和群复合头像不带该标记。十款豆子 Bot 头像复用已有七款悬停动效，仅在支持悬停的指针上启用，减少动态效果时关闭。Bot 回复、交接和审批保留原有颜色。审批卡片与输入框同宽并左右对齐。

成员的问题在本群输入框上方显示，并标明提问成员。选项、自由输入和作答均复用现有问答组件，答案发回该成员原始执行 Session。隐藏待回答问题后保留“继续回答”入口，不会自动作答或取消请求；已回答或取消的请求会移除。其他群和 Bot 私聊的问题保持独立。普通群消息仍会排队，不会被隐式当作待回答问题的答案。

群状态表示允许成员工作、暂停或停止，状态及控制行跟随输入框共用的宽度并居中对齐；活动信息表示本群驱动与实际执行成员。暂停阻止新的派发，不取消已经运行的工作；嵌套派活尚待执行时，调用方继续等待“继续”或“停止”。接力预算耗尽时保留尚未执行的目标，点击“继续”接续同一轮；普通用户消息保持排队，不重置预算或恢复已暂停轮次。明确选择打断才开启有独立预算的新一轮，取代待执行工作，并等待旧调用链结束后再执行新任务，历史仍保留。未知结果阻止自动推进排队输入；明确发送的新调整指令保留这些结果供核对。排队输入遇到手动暂停或错误暂停时仍需明确继续。暂停提示对应已保存的原因，只有所有者暂停使用手动暂停说明，不把未识别原因归为用户操作。停止取消所捕获的本群轮次，并等待其所属工作及原审批结束，不取消其他群或私聊。控制请求携带预期轮次和代次，旧操作不能停止后来的新轮次。控件的等待状态仅适用于捕获的群、运行 ID 和代次，旧响应不会禁用其他群或新轮次的控件，也不会解除较新操作的等待状态。

审批策略、工作区指令、工作目录和显式上下文通知不会把空闲成员标为忙碌。派发时保留队列中的上下文，使其进入任务已保存的模型输入。单独修改权限不会启动回复；审批策略通知在停止后也会保留。正在执行或存在真实任务输入时，仍阻止重复派发。成员执行名额申请失败会保存任务错误，不留下没有诊断的已接纳任务。

群输入框把消息已持久接受的结果显示为系统提示，与成员发言分开。提示只按本群实时活动显示正在处理的成员，区分暂停队列与实际执行，并丢弃旧 Session 绑定或连接的回执。明确的打断入口仍提交原编辑器内容，保留附件、成员引用和失败恢复。

侧栏每个群名旁的小图标区分实际执行、成员等待审批或确认，以及结果已经保存并发布的本轮完成状态。图标只读取当前群的代次和原执行成员交互；空群保持待命，暂停、停止、失败、结果未确认及同步中的状态均不显示完成。悬浮提示说明当前状态，共用的旋转图标尊重减少动态效果设置。

独立的 `katcats_chats_v3` 存储域保留创建及设置意图、已准入用户消息及初始接收者、独立 Session 绑定、成员进度、已完成回执、业务任务及阻塞解释义务。相同输入框请求 ID 复用已保存输入，同 ID 的内容变更在解析上传文件前被拒绝。重启暂停未完成工作；恢复仅核对已证实成员输出并补写聊天记录，不自动重复结果未知的外部工作。成员设置或群成员变化后，历史回复仍保留当时身份。群成员工作时也可以移动群聊，操作只改变归组，不重命名 Session 或移动文件。

首次打开 v3 时，产品导入已提交的 `katcats_chats_v2` 数据，否则导入最初的 `katcats_chats` 数据，包括未完成设置、消息引用、回执及所有者元数据。两个前代均不改写。导入失败可以重试；已提交的 v3 不会被旧代替换，损坏的 v2 不会退回 v1。缺少负责人、职责或输入字段时沿用兼容默认值，历史根工具位置转换为明确标记的工具来源。已有创建助手成员的设置保持到所有者编辑，但不接受新派活。成员变更后保留原执行绑定，移除旧创建助手时清空相应负责人，之后不能重新加入。不支持降级。

群输入框的 `@` 菜单只列当前普通成员，显示豆子 Bot 头像和姓名。选中的引用携带群与 Bot 身份，不使用私聊 Session 身份；序列化及 Host 准入重新核对群籍，拒绝外群、创建助手及已移出成员。完整的带引号文件引用及明确路径不用于成员派发，原始附件文本保持不变。目录不可用时返回空候选，不退回全局会话列表；成员点名不读取私聊历史。

每个已接纳任务在群记录中显示实际发起者、接收成员、任务和生命周期。排队记录只确认接纳，不代表已经执行或完成；开始和终态记录跟随已保存的执行状态，成员发言仍为独立消息。取消表示派发前停止，结果未确认表示外部结果仍需核对。恢复记录只展示保存数据能够支持的状态，并明确标注恢复，不虚构历史执行时间。稳定的任务状态身份避免重试及冷恢复重复显示；群记录写入无法确认时，只暂停当前群并显示错误，停止后续派发。

群设置中的“显示交接记录与状态”在点击后独立自动保存 `showHandoffRecords`，不提交或丢弃其余设置草稿。Host 确认后生效；保存失败时保持已确认的值。新群显式启用；旧记录缺少该字段时仍按启用显示，读取时不迁移或改写原存储代次。关闭后隐藏本群已有及后续的交接正文卡和任务进度卡，用户消息与真实成员回复仍显示；重新启用后从保留记录恢复展示。仅修改该显示项的更新，包括 Host 同时处理群聊移动的更新，可在协作中保存，保留运行轮次、代次、派发记录及 Session 日志，不暂停工作。其余设置沿用既有未保存修改和忙碌保护；修改显示偏好不删除历史。

成员已完成回复会显示实际通过 `present` 登记文件的原[交付卡片](../../client/ui-deliverables/README.zh.md#explicit-deliveries)。群聊先校验原执行会话记录的任务认领与已完成收尾消息，再在该执行会话的保留引用下渲染共享 Factory。预览和原生操作保留其文件系统授权与事件坐标；模型填写的路径不产生卡片。关闭交接记录仍显示成果卡；成员离群后，只要群仍保留原执行会话，也可显示历史成果。切走或连接断开时释放当前显示结果的会话引用；重新打开从保存的事件重建卡片，不运行模型。

工具请求审批前，群执行成员先 flush 并发布其已完成且带工具调用的 assistant 消息中的公开文字，沿用原消息身份；思考、被中断输出、私聊回合和后续最终回复不在这次提前发布中。审批尚未作答时，群里已经可以看到成员的真实发言，拒绝或停止不会撤回这段文字。恢复只补发缺失消息，不重复工具工作。成员提示要求执行工具前简短回应；如果实际只生成工具调用，则保持没有发言，由任务记录显示真实状态。

成员失败结果结算前，[模型请求恢复](../../llm/llm-retry/README.zh.md)可以在配置预算内重试格式异常的响应，不重复已完成的工具步骤。成员结果未确认时保持群聊暂停，不自动重放任务。已记录的执行报错、模型响应格式异常、输出上限、取消和步骤受阻分别显示固定诊断，不向群内复制原异常内容。格式异常导致的暂停轮次提供“结束失败轮次”，替代无法恢复的“继续”操作；之后发送新指令即可开启新一轮，原有结果和历史保留。操作区只显示一份同义说明，错误代码保留在折叠详情中。

<a id="saved-memories"></a>

## 已保存记忆

独立 `/memory` Host 入口拥有 `katcatsMemory` 服务与 `katcats_memory` 存储域。私聊读取本 Bot 及团队作用域，群成员读取当前群及团队作用域；聊天容器没有记忆工具或模型提示词。成员不提取私聊原文或摘要。普通 Bot 只写当前作用域，私聊中的创建助手还可写团队事实。只有所有者能审阅条目后跨作用域复制；副本保留所选来源版本、作者和时间，之后修改或删除来源不会改变副本。

所有者可以查看、搜索、编辑、删除和明确分享条目，编辑、删除及分享检查所见条目版本。`maxEntries`、`maxEntriesPerScope`、`maxTextChars`、`recallLimit` 和 `maxPromptChars` 配置保存与模型可见上限。降低容量后无法容纳现有数据时明确报错，不丢弃数据。工具在持久写入后才确认，准入后取消可能与已保存条目同时存在，结果不确定时先检查条目再重试。

群内审批引用原执行 Session 的待审批请求，展示其提供的选择并保留取消生命周期，不自动授予访问，也不把请求移到聊天容器。等待审批时，停止群聊仍可取消本群所属工作。

<a id="automation-task-lists"></a>

## 自动化任务列表

Bot 或群设置中的自动化按钮打开当前设置 Session 专属的任务列表，不显示搜索框。集中的“自动化任务”页面按 Bot 或群聊展示全部保留任务，无法匹配的记录列在“未关联任务”中；只有此页面提供任务名称、指令及所属对象名称搜索。两个视图均保留已启用和已结束状态筛选，共享公开 Schedule 目录，在任务变化或连接重置后刷新；打开列表不启动 Agent，也不读取 Session 聊天历史。

任务归属根据已保存的 Session 绑定确定：成员私聊 Session 归该 Bot，群根 Session 或保留的成员执行 Session 归该群，包括成员离群后仍保留的执行绑定。群内创建的任务不出现在成员私聊列表中。Bot 改名或移动逻辑分组不重写任务。已有任务 ID、Session 绑定、时间规则及投递历史仍保存在 Schedule 域，无须迁移。打开任务时沿用原始 Session 绑定，复用现有 Schedule 详情页中的编辑、删除和已保存投递历史。

打开自动化列表或任务详情时，设置表单继续挂载，只要该设置标签仍保留挂载，未保存修改就继续保留。目录展示保留任务与投递状态，不表示执行结果已经确认；群定时任务的支持范围见[下方限制](#known-limitations-and-deferred-work)。

<a id="persistence-and-recovery"></a>

## 持久化与恢复

新增 `katcats_team` 存储域使用版本 1，不迁移其他产品的数据。分组、成员与未完成操作状态保存在同一个原子全局记录中。成员仅在私聊 Session 持久化后显示。`pendingRename` 保存名称或模型设置的完整目标，直到 Session 刷盘与成员记录均提交。模型输入被拒绝且 Session 未变更时清除目标。模型切换已接受或结果不确定时，失败保留目标并报告设置未完成，后续快照或重启重试，不提前报告成功。仅改名失败时尽可能恢复旧标题。未知版本与无效身份会报错，不重置数据。

成员身份独立于私聊 Session ID。插件使用公开 Session API 和成员作用域的提示词分区，不修改智能体循环。测试使用临时目录与合成模型适配器，与开发用户数据分开。

## Model Experience

### 成员身份

#### What the model sees

成员保存的名称和职责替换其私聊 Agent 的产品身份分区。私聊与群聊成员的提示词均指定“瑞华云财务共享团队”，即使旧对话含有旧产品名称，之后的自我介绍也使用新名称。已保存的职责与历史回复不会改写。没有职责时使用以下原文：

##### 通用助手职责

```markdown
You are a general assistant. Work with the user to establish your role.
```

#### Token effect

名称和当前职责进入每次组装的系统提示词。修改职责影响下一次组装，不改写已经进行中的请求。现有系统消息事件记录实际生效文本。

#### KV Cache effect

成员身份不变时保留该提示词分区。修改名称或职责会替换文本，可能使受影响的提示词前缀缓存失效。

### 模型选择

#### What the model sees

固定模型变更沿用现有 [Agent 模型选择机制](../../core/agent/README.zh.md)：下一次准入的请求将模型切换提示与路由记录在 Session 日志中，不改写之前的请求或消息。

#### Token effect

路由变化会向下一次准入请求加入现有模型切换提示。选择模型本身不会发起模型请求。

#### KV Cache effect

选择其他模型可能使请求进入不同的提供方缓存；提供方缓存与淘汰策略不属于本包职责。

### 对话工具

#### What the model sees

成员工具的定义仅进入所属 Agent 的请求，调用与结构化结果沿用现有工具日志；职责变更进入下一次组装的身份分区。工具指导要求用户明确安排长期身份，普通任务保留在当前对话。

#### Token effect

工具定义、结果与已保存职责会消耗请求 token；主成员与普通成员使用不同工具集合。

#### KV Cache effect

所属成员保留稳定的工具定义；修改已保存职责会在下一次组装时改变身份前缀。

### 群聊

#### What the model sees

成员请求加入名录、已保存职责、负责人及复核指导，以及选取的公开群消息。当前任务保留原始内容，结果元数据引用每份回复的唯一正文。历史查询通过已记录的工具结果返回原文、图片及附件。交付指导要求可直接使用的文字或实际 `present` 登记；重要任务还须通过对应内容版本的复核。派活结果包含已确认成员结果，不只是排队确认。提示词、带版本上下文清单、复核证据和消息均沿用正常 Session 日志。公开输出来自实际成员 Session，并保留当时身份；群容器没有模型身份或请求。

#### Token effect

仅实际派工成员发起模型请求，无关成员不再仅为决定是否跳过而调用模型。持久化消息身份避免反复追加已经提供的群历史，不同消息仍分别保留。已有执行会话历史、摘要、工具定义、历史查询和独立复核仍消耗 token。确定性测试验证派工和去重，不证明真实模型质量或计费节省；后两者必须保持模型及任务相同，对照实际缓存输入、未缓存输入、输出、费用、耗时及交付验收结果。

#### KV Cache effect

修改名录或指导可能使受影响前缀缓存失效；身份不变时保留各独立 Session 内的成员前缀。

### 作用域记忆

#### What the model sees

作用域记忆工具与序列化条目使用公开工具和系统提示词机制，以及普通请求日志。记忆事实属于不可信数据，不授予权限，也不能选择其他 Bot 作用域。提示词报告省略条目数量，召回可以查找受限上下文中未包含的已保存事实。

#### Token effect

记忆工具定义、所选条目和召回结果在配置上限内消耗 token。删除事实不清除已经记录它的历史请求。

#### KV Cache effect

可见记忆变化会替换提示词章节，可能使受影响前缀缓存失效；未变化条目保留稳定的序列化内容。

## Known Limitations and Deferred Work

- 动态跟随覆盖产品消息准入及产品管理的群派活或继续操作，不改变无关的直接 SDK、ACP 或定时 followup。
- 群停止会等待已经通过公开 Session API 准入的选模元数据查询结束，该 API 不接受取消；已捕获轮次停止后不会再派发成员模型请求。
- 群回执展示成员最终文字、Markdown 文件链接，以及已完成回复实际登记的最终文件原卡片。内嵌可视化及其他工具结果卡保留在执行成员的 Session 中。文件登记成功后若发生错误或中断、没有已完成收尾回复，登记仍保存在该 Session 中，但不产生最终群成果卡；重试前应先检查已保存结果。
- 召回使用不区分大小写的子串匹配，不使用向量。凭据模式检测属于启发式检查，不回显可识别秘密或将其存入记忆，但无法删除消息或工具调用中已经提交的输入。删除保留先前分享的副本与请求日志。
- 自动化列表将已有 Schedule 记录关联至 Bot 或群聊。群定时执行尚未接通：Schedule 服务直接向原 Session 投递，而群成员只接受产品调度的群内工作。任务出现在列表中或已保留投递回执，不代表任务已运行或完成。私聊派活、群定时投递与更完整的能力对标仍列在开发计划中。
- 设置页显示创建时分配的工作目录。切换现有成员目录需要后续文件与权限生命周期处理。
